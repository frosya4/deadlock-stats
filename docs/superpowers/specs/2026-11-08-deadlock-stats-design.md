# Deadlock Stats — сервис разбора демок

## Зачем
Владелец (далее «я») скидывает друзьям ссылку на сайт. Друзья загружают туда `.dem`-файлы Deadlock, сервер их разбирает и показывает подробный интерактивный отчёт по матчу. Тяжёлые демки (300–400 МБ) не хранятся, остаются только лёгкие данные (~1–2 МБ на матч) в отдельной папке на каждый матч, которую можно просто удалить.

## Цели
- Загрузка `.dem` через браузер (drag&drop, прогресс загрузки и обработки).
- Обработка на сервере: тот же конвейер, что уже работает локально (см. «Что уже есть»).
- Список разобранных матчей (дата, длительность, победитель, герои) → страница матча.
- Интерактивный отчёт:
  - нетворс **по каждому игроку** отдельно: линии включаются/выключаются (по игроку, по команде, «все»), подсказка при наведении показывает значения всех видимых игроков в эту минуту;
  - то же для полученного золота и GPM (по времени и итог по источникам);
  - клик по игроку открывает его карточку: билд по времени (с проданными), прокачка способностей, смерти (список + точки на карте), урон кому/от кого;
  - остальное из текущего отчёта: таблица игроков, объекты, матрица урона, точность, хронология убийств, чат.
- Повторная загрузка той же демки не обрабатывается заново — сразу открывается готовый матч (ключ — match id из демки; дополнительно хэш файла, чтобы не парсить заново).
- Скачивание данных матча (JSON/CSV).
- Отдельная страница-визитка проекта на GitHub Pages: что это, скриншоты, ссылка на сайт, инструкция по установке на свой сервер.

## Не цели
- Регистрация, аккаунты, пароли. Доступ — у того, кому дали ссылку (сайт не индексируется: `robots.txt` disallow, `noindex`).
- Хранение исходных демок после обработки.
- Публичная статистика по игрокам между матчами, рейтинги (возможно позже).
- Просмотр/воспроизведение самой демки.

## Анти-цели (провал, даже если «работает»)
- Сервер падает или забивается диском/памятью от нескольких одновременных загрузок.
- Отчёт тормозит или не читается на телефоне.
- После очередного патча Deadlock всё молча ломается без понятной ошибки пользователю.

## Ограничения
- Хостинг: VPS владельца, доступ по IP, домена нет. Адрес вида `<ip-через-дефисы>.sslip.io`, HTTPS через автоматический сертификат (Caddy / Let's Encrypt).
- Код — публичный (или приватный, на выбор) репозиторий на GitHub; визитка — GitHub Pages из того же репозитория.
- Загрузка до ~600 МБ на файл.
- Интерфейс на русском.

## Что уже есть (рабочий прототип, Windows)
1. **Парсер** — `haste` (Rust, github.com/blukai/haste) с двумя патчами под текущий патч игры:
   - `crates/haste_core/src/fieldmetadata.rs`: перед `vartype::parse` из типа вырезаются аргументы шаблона после запятой (`CNetworkUtlVectorBase< X, NetworkVar_..., -1, int >` → `CNetworkUtlVectorBase< X >`);
   - `Parser::visitor_mut()`.
   Свой пример `dldump.rs`: пишет `ents.jsonl` (снимки контроллеров/павнов/правил/объектов каждые 30 с + финал) и `msgs.tsv` (user messages 300–399, game events 205/207, hex).
2. **Декодирование** (Python + protobuf, протофайлы из valveprotos-rs): главное — сообщение `PostMatchDetails` (id 316) → `CMsgMatchMetaDataContents` = полный пост-матч отчёт (игроки, предметы, смерти с координатами, объекты, матрица урона, статистика по времени, источники золота). Плюс чат (314), убийства (319), боссы (347), пинги (303).
3. **Справочники** — из файлов игры: `heroes.vdata_c`, `abilities.vdata_c` (через Source2Viewer-CLI), локализация RU/EN; id предмета = MurmurHash2(имя, seed 0x31415926).
4. **Отчёт** — статичный HTML с данными внутри (`report_template.html`).

## Решения, принятые владельцем
- Вариант «всё на VPS, код на GitHub» + визитка на GitHub Pages.
- Доступ только по ссылке, без пароля.
- Дубликаты не обрабатываются повторно.

## Мои решения (можно оспорить)
- **Стек сервера:** Python (FastAPI) для загрузки/API/раздачи + бинарник на Rust (наш `dldump`, собранный под Linux) + Python-декодер. Причина: всё уже написано на них.
- **Фронтенд:** одна статичная страница (без сборщика), графики на uPlot или Chart.js с CDN; данные матча грузятся как JSON.
- **Очередь:** одна задача обработки за раз (парсинг ~5 с, но памяти/диска нужно), остальные ждут; статус через опрос.
- **Хранение:** `data/matches/<match_id>/` — `match.json`, `postmatch_raw.json`, CSV, `meta.json` (когда загружено, хэш). Демка пишется во временный файл и удаляется после обработки (и при ошибке).
- **Справочники** генерируются один раз скриптом из файлов игры на моём ПК и коммитятся в репозиторий (`refs.json`); обновление после патча — тот же скрипт.
- **Деплой:** Docker Compose (приложение + Caddy). Один скрипт установки на чистый Ubuntu.
- **Защита от мусора:** проверка сигнатуры `PBDEMS2`, лимит размера, лимит одновременных загрузок.

## Оставлено исполнителю
Структура кода, выбор библиотеки графиков, вёрстка, тесты (минимум: обработка эталонной демки даёт ожидаемые K/D/A и нетворс).

## VPS
Ubuntu, 8 ГБ RAM, 100 ГБ диска.

## Репозиторий и ссылки
- Репозиторий публичный (нужно для бесплатного GitHub Pages). В нём только код; данные матчей — только на VPS.
- Адрес сайта на визитке не публикуется.
- Ссылки, которые раздаёт владелец: главная `https://<ip>.sslip.io/` (загрузка + список матчей) и прямая на матч `https://<ip>.sslip.io/m/<match_id>`. Загружать может любой, у кого есть ссылка (и владелец, и друзья).
