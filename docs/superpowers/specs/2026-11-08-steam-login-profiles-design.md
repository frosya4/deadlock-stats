# Вход через Steam, профили игроков, обработка по кнопке

Одобрено владельцем в чате 2026-11-08.

## Зачем
Чтобы друзьям не приходилось искать и загружать файлы демок, они входят через Steam, видят свои последние матчи и одной кнопкой отправляют любой из них на обработку. Работает как OpenDota: профили публичные, обработать можно любой матч, в том числе чужой.

## Что делаем
1. **Вход через Steam** (Steam OpenID 2.0, `https://steamcommunity.com/openid/login`). Ни пароля, ни Steam API key не нужно, сайт получает только SteamID64.
   - Правый верхний угол на всех страницах: кнопка «Войти через Steam». После входа на её месте аватарка и ник, клик ведёт в свой профиль; рядом «Выйти».
   - Аватарка и ник — из публичного профиля Steam (`https://steamcommunity.com/profiles/<id>?xml=1`) или из deadlock-api; если не получилось, показываем Steam ID.
   - Сессия: подписанная cookie (HttpOnly, Secure, SameSite=Lax), 30 дней, секрет — переменная окружения / файл на сервере, не в репозитории.
   - Ответ OpenID проверяется на сервере Steam (`check_authentication`); `return_to` и `realm` фиксированы на адрес сайта.
2. **Профиль `/p/<account_id>`** (account_id = SteamID64 − 76561197960265728; принимать и SteamID64).
   - Публичный: открыть может любой, у кого есть ссылка на сайт.
   - Последние матчи из `https://api.deadlock-api.com/v1/players/<account_id>/match-history`: дата, герой (портрет), У/С/П, победа/поражение, длительность.
   - Состояние каждого матча: «Обработан» → ссылка на отчёт; «Обработать» (кнопка, только после входа; без входа — «Войдите через Steam, чтобы обработать»); «В очереди/обрабатывается» с прогрессом; «Демка недоступна», если salts не отдают URL демки.
   - Кэш ответа match-history на сервере ~5 минут, чтобы не долбить API.
3. **Обработка по кнопке** = существующий путь `/api/fetch` по номеру матча (salts → replay*.valve.net), но:
   - только для вошедших через Steam (и у существующего `/api/fetch` тоже требуется вход);
   - лимит **2 обработки в час на аккаунт**; плюс остаются общие лимиты: очередь до 5, 60 скачиваний в час на сервер, проверки диска;
   - уже обработанный матч не качается повторно — сразу «Обработан»;
   - при отказе — понятная причина по-русски (лимит, очередь полна, мало места, демка недоступна).
   - Записывать, кто запустил обработку (account_id) в meta матча — для будущих платных лимитов.
4. **Страница необработанного матча `/m/<номер>`**: если матча нет на сервере, но номер числовой — базовая информация из `.../v1/matches/<id>/metadata` (счёт, герои, длительность, игроки со ссылками на профили) и кнопка «Обработать».
5. **Связи**: в отчёте ник игрока ведёт на `/p/<account_id>` (account_id есть в postmatch). На главной — поиск: номер матча, Steam ID или ссылка на профиль Steam.

## Не делаем
- Платные лимиты (возможно, позже — заложить только учёт, кто запускал).
- Список друзей, приватные профили, ограничение входа списком.
- Хранение чего-либо о пользователе, кроме того, что нужно для сессии и лимитов.

## Остаётся как есть
- Загрузка файла `.dem` без входа (свои лимиты по IP).
- Общий список матчей на главной, прямые ссылки на отчёты, noindex.

## Анти-цели
- Можно войти под чужим Steam ID (подделка ответа OpenID) — провал.
- Сайт падает или зависает, если deadlock-api недоступен: профиль должен показать «API временно недоступен», а отчёты — работать.
- Обход лимита 2/час через параллельные запросы.

## Оставлено исполнителю
Хранение сессий/лимитов (sqlite рядом с индексом — ок), вёрстка в стиле v2 (тёмная тема), библиотека для OpenID (или вручную), тесты: подделанный OpenID-ответ отклоняется, лимит 2/час, кнопка без входа недоступна, профиль при недоступном API.
